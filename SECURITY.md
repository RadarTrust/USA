# Security Policy

## Project

**RadarTrust USA — Professional Portfolio & Credentials**

This security policy applies to the RadarTrust USA repository, its published website, and associated project components maintained by the repository owner.

## Supported Versions

Security maintenance is provided for the latest published version of the project on the `main` branch.

Older versions, historical commits, forks, and third-party copies are not actively supported.

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it privately through GitHub's **Private Vulnerability Reporting** feature.

Do not disclose sensitive vulnerability details in public issues, pull requests, or discussions.

When reporting a vulnerability, please include:

- A clear description of the issue.
- The affected component or file.
- Steps to reproduce the issue safely.
- The potential security impact.
- Suggested remediation, if available.

Reports will be reviewed as resources permit. Acknowledgment, remediation, and disclosure timelines are not guaranteed.

## Access Control and Repository Integrity

Repository write access is restricted to explicitly authorized maintainers and applications.

Unauthorized modification, deletion, deployment, credential access, or disruption of project resources is prohibited.

External contributions and proposed changes are subject to maintainer review and approval.

## Credentials and Sensitive Information

Passwords, access tokens, API keys, private keys, and other sensitive credentials must not be committed to this repository.

Any exposed credential should be revoked or rotated promptly.

## Responsible Security Research

Security research must comply with applicable laws and platform policies.

Do not perform destructive testing, denial-of-service attacks, unauthorized data access, or activities that disrupt the website or its users.

## Intellectual Property

Unless expressly licensed otherwise, the project's original content, branding, graphics, and source materials remain the property of their respective rights holders.

Public visibility of the repository does not, by itself, grant permission to reuse copyrighted material. Applicable licenses and third-party rights must be respected.

## Security Contact

Please use GitHub Private Vulnerability Reporting for confidential security disclosures.
